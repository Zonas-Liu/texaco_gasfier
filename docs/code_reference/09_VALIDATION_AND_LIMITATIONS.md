## 9.1 四种不同的可信度

| 层级 | 要回答的问题 | 当前证据与边界 |
|---|---|---|
| 程序/协议正确 | 输入、索引、输出、失败路径是否按约定执行？ | unittest、输入/解析/搜索测试；不代表全部参数组合可解 |
| 离散方程求解 | 本次迭代是否达到既有SUM修正量阈值？ | KONVER与退出码；不是完整原方程残差范数，也不是模型误差 |
| 物理账闭合 | 三截面元素、总质量、能量是否独立闭合？ | 7组固定工况及联合设计通过元素/总质量核算；**尚未完成独立全炉能量闭合** |
| 工程预测能力 | 温度、组分、产汽能否预测装置？ | 尚缺覆盖操作域的实测验证、热力学/动力学追溯与网格无关性证据 |

模型能收敛、元素能守恒、与Fortran一致，是三个不同事实。忠实移植也可能忠实保留旧程序的近似和缺陷。修改常数后，新的晋华炉结果应与新物性基线比较；不能为恢复旧温度而任意调整源项或容差。

```powershell
.venv\Scripts\python.exe numeric_test/check_element_balance.py --output numeric_test/python_output/manual-element

```

使用新的输出目录，避免覆盖已接受的证据。性能脚本会保存失败工况，因此进程退出0并不保证每个case收敛；检查`summary.json`中的`returncode`及各候选结果。元素审计标准套件遇未收敛会停止。扩展套件保留未收敛状态并继续其余工况，`accepted`同时要求求解成功、总质量及元素账通过，整批存在未通过项时退出码为2。

`run_regression.py`默认比较旧提交，属于移植审查工具；物理模型变更后不要把它的默认基线当成现行正确模型。`compare_results.py`和`comparison_summary.txt`保留历史Fortran比对；本轮文档整理没有重新编译原Fortran。

## 9.4 元素核算的独立性

核心入口为[check_element_balance.py](../../numeric_test/check_element_balance.py)的`ledger(state)`：

1. 根据原始煤/水/氧化剂/CO₂输入独立建立C/H/O/N/S和灰入口账；不是把出口归一化成入口。
2. 用各物种原子计量矩阵乘完整`FEMF`，加`WE·X`残碳和`WE·(1−X)`灰，取得第30格与末格截面流。
3. 比较进口→燃烧室、燃烧室→废锅、进口→废锅，阈值每项`max(1e−6kg/h, inlet×1e−8)`。
4. 总进口直接加总煤浆、纯氧、氧气携带的N₂、稀释CO₂。总出口由八种湿气摩尔流乘运行摩尔质量，加总固体`WE`计算。三组总质量差分别与`max(1e−6kg/h, 总进口×1e−8)`比较。
5. 独立检查煤元素、灰及煤内水质量分数之和，以及运行摩尔质量与该次原子量是否一致。保留逐格诊断、源项速率和旧缩放缺陷预测。

副产蒸汽在独立水侧，不加入合成气入口/出口账。灰作为惰性整体账项，不能同时把假想SiO₂中的氧计入ELO，也不能将全部WE都当未反应碳。使用舍入文本或UI百分数进行微量误差验收会损失证据。

扩展套件包括22种工况，覆盖输入的当前计算模式、负荷、氧煤比、煤浆浓度、氧气纯度、二次氧/CO₂、煤内水/硫/灰、废锅高度/网格、炉压、联合反算及零挥发分诊断。各工况共享启动时的输入快照，分别在独立子目录使用`KTRL=1`初始化。

```powershell
.venv\Scripts\python.exe numeric_test/check_element_balance.py --suite expanded --output numeric_test/python_output/mass-balance-new
```

`--cases`可选择该套件中的案例，`--max-iterations`可显式增加迭代上限。重试应使用独立输出目录，并同时保留首次失败记录。2026-11-12实算证据见[多工况质量与元素审计](../MASS_BALANCE_CHECK_2026-11-12.md)。

## 9.5 尚未解决的物理和数值问题

| 项目 | 源码位置/表现 | 当前处理及下一步 |

| 经验温度/平衡 | 固定TW、甲烷化范特霍夫近似，水侧压力不反馈TW | 需热阻网络或实测闭合，不能视为完整锅炉设计 |
| 收敛定义 | Σ原始Δu判据，不显式约束所有原方程R | 增加独立方程残差与能量检查需另做尺度/容差设计 |

| 单例/服务并发 | COMMON、cwd和输出文件均为共享状态 | 同目录单计算；多用户任务应改为进程与工作目录隔离 |

## 9.6 常见故障定位

| 症状 | 优先核查 | 不应采用的捷径 |
|---|---|---|
| 一启动就报输入错误 | 行号、D指数、整数控制、绝压/绝温、煤分析基准 | 自动截整数或猜测单位 |
| 重启网格不匹配 | KTRL、工作目录START优先级、11×NZRE值数 | 截断/补零后继续 |
| 进度称running但界面不变 | 任务PID、实际cwd、进度JSON时间戳、stdout/stderr | 仅凭HTTP200认定求解正常 |
| 迭代数增加/残碳抖动 | 模型分支、X差分步长、线性后端、初猜和煤质 | 放宽SKON掩盖 |
| 目标设计失败 | 内层是否收敛、目标相对有效壁温、边界是否括住目标 | 越界外推或只改显示温度 |
| 元素缺口 | 质量常数配置、源项行缩放、二次进料、灰/残碳分开 | 归一化出口组分强行闭合 |
| 新旧产汽差异 | QKW、汽包绝压、给水同压焓、当前/旧IF97版本 | 只校正一个乘数来匹配旧表 |
| 图表坐标/固体指标奇怪 | H历史坐标、WE总固体、FOC与common.X不同 | 将旧字段名称当成物理定义 |

## 9.7 变更与验收约定

- 新参数追加文件末行，同时更新COMMON默认、校验器、两套输入保留逻辑、Web元数据、本手册第5章和AGENTS。
- 修改反应时先检查原子计量矩阵乘源项为零，再检查方程行缩放一致；之后真实求解并做三截面核算。
- 修改焓/常数时保持生成焓和显热参考态一致，注明KMODEL0兼容决策；不以Fortran一致替代物理正确性。
- 修改缓存/雅可比时证明依赖格号与状态有效，测试缩放后线性系统后向误差；再比较完整状态与耗时。
- 修改外层设计时测试可达、不可达、内层失败、边界初值、联合目标及START保护。
- 接口变化以实际输出快照/解析测试为证据；历史输出缺项显示缺失，不能用当前输入拼接旧结果。
- 文档和注释变更应保持数值行为不变；生成符号索引并检查链接，另运行相关既有测试。

```powershell
.venv\Scripts\python.exe scripts/check_docs.py --write-index
.venv\Scripts\python.exe scripts/check_docs.py
```

生成器使用AST读取源码，不导入Streamlit/Flask、不运行求解器。第10章只负责符号定位，其他章节必须人工维护公式、基准、假设和失败语义。
